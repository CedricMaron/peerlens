# EXTRACT — Problem

Extract the scientific problem this research addresses.

A problem is not a topic, not a technique, and not a goal. It is a specific
difficulty, gap in capability, or unresolved question in the world or in the
literature, that has consequences if left unresolved.

## What to extract

One primary problem statement (`P1`), plus any distinct sub-problems the
material genuinely treats separately.

Useful `details` keys:

- `domain` — the scientific field or application area
- `who_is_affected` — whose work or outcomes are impacted
- `consequence` — what goes wrong because this problem is unsolved
- `scope` — the boundaries the researcher places on the problem
- `motivation_type` — e.g. `empirical`, `theoretical`, `practical`, `stated_only`
- `evidence_of_problem` — what the material offers to show the problem is real

## Guidance

- Separate the *problem* from the *proposed solution*. Researchers frequently
  describe their method where the problem should be. If the material only
  describes a method, extract the problem it implies and mark it `inferred`.
- Separate the *problem* from the *research gap*. The problem is the real-world
  or scientific difficulty; the gap is what prior work has failed to resolve.
  The gap belongs to its own section.
- Record whether the material actually establishes the problem exists, or merely
  asserts it. Both are legitimate extractions; only one is evidence.
- If the framing shifts between inputs (an early note frames it one way, a later
  draft another), record that in `notes`.
